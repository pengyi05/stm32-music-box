# AT89C52 音乐盒 / 音频播放系统

基于 AT89C52（8051 架构 8 位单片机）的音频播放系统。从原理图绘制、PCB 排版、打板焊接，到 Keil 编码与整机调试，完成完整的硬件与软件闭环。

> 独立完成：电路原理图设计 → PCB 布局布线 → 打板 → 器件焊接 → 固件开发 → 联调出声

## 五、核心实现

### 5.1 音频播放原理

音频本质上是**频率和幅度随时间变化的信号**。数字音频通过采样将连续信号离散化，播放时再以固定速率还原。

本项目采用 PWM 方式模拟音频输出：

- 蜂鸣器只能输出"响"和"不响"两种状态
- 通过**改变 PWM 占空比**模拟不同振幅 → 产生音高与音量的变化
- 通过**改变定时器重装值**控制 PWM 频率 → 对应不同的音符音高

```
音符音高 ←→ 定时器重装值（频率）
音量强弱 ←→ PWM 占空比（幅度）
```

### 5.2 时序精度（本项目最关键的技术点）

播放质量的核心瓶颈**不是存储空间，而是时序精度**。

8051 的定时器在 12 分频模式下，一个机器周期为 12 个振荡周期。以 11.0592MHz 晶振计算：

```
机器周期 = 12 / 11.0592MHz ≈ 1.085μs
```

因此：

- 音高由**定时器重装值**决定，重装值算错会导致音调明显偏差
- 音符时值由**中断服务程序延时或计数**控制
- 中断服务程序耗时必须显著小于音符周期，否则会出现音调不稳或杂音

**注意 8051 与 STM32 的关键差异**：8051 是 8 位架构，访问 `int`/`long` 类型变量需要多个机器周期；变址运算、数组结构体赋值都会显著影响执行效率。因此**音频数据表的组织方式与读取方式对 8051 的运行效率影响很大**——这是本项目最值得记录和复盘的点。

### 5.3 音频数据存储方案

由于音频采样数据量较大，在 8051 上采用了两种方案之一（按你的实际情况选择）：

**方案 A：单音（音调）驱动**
每个音符存一个字节的频率值，用 `switch-case` 或查找表播放旋律。数据量极小，8KB Flash 足够存多首曲子，但只能演奏旋律，无法还原真实音色。

**方案 B：采样波形驱动**
每个音符存若干个采样幅度值（如8位无符号），由定时器中断逐点输出 PWM 模拟。数据量大（需外部存储扩展），但可以还原简单音效。

> 请按你的实际实现方式选择或删除本节。

**进阶方向（进阶方向）**

若使用 STM32 等具备 DAC 的平台，可用 DMA 双缓冲实现更复杂的音频播放：

```
Buffer A ──正在播放──▶
Buffer B ──后台填充──▶   两者交替使用
DMA 半传输中断 → Buffer 前半部分已消耗，可安全重填
DMA 全传输中断 → Buffer 全部消耗，切换到另一个 Buffer
```

这样实现了数据供应的流水线化，几乎消除卡顿。

## 六、遇到的问题与解决

> 这一节是本项目最有价值的部分。**面试中被问得最多的不是"你做了什么"，而是"你遇到了什么问题、怎么解决的"。**

| 现象 | 可能原因 | 解决方法 |
|---|---|---|
| 蜂鸣器不响 | 定时器未正确配置 / 引脚未接 | 检查定时器模式、重装值与引脚连接 |
| 音调明显不准 | **定时器重装值计算错误**，未考虑机器周期 | 重新计算：周期 = (65536 - TH1*256 - TL1) × 12 / 晶振频率 |
| 声音断续、有杂音 | 中断执行时间过长或时序抖动 | 精简 ISR，移出显示等非必要逻辑到主循环 |
| 同一个音符时长不一 | 中断计数方式不统一 | 统一采用定时器中断计数，而非函数调用链延时 |
| 按键误触发 | 无消抖 | 加入 10ms 采样 + 20ms 确认的状态判定 |
| 数据表读取异常 | **`code` 关键字缺失**（8051 特有） | Flash 中的常量表必须加 `code` 声明，否则会存入 RAM 占满内存 |

**最后一条是 8051 开发中最常见的坑**，也是面试时提到能体现你真的踩过这类坑。
