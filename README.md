# AT89C52 音乐盒 / 音频播放系统

基于 **AT89C52（8051 架构 8 位单片机）** 的音频播放系统。从原理图绘制、PCB 布局布线、打板焊接，到 Keil 编码与整机调试，完成完整的硬件与软件闭环。

> 独立完成：电路原理图设计 → PCB 布局布线 → 打板 → 器件焊接 → 固件开发 → 联调出声

---

## 一、项目概述

**一句话描述：**

> 用 8051 的定时器中断驱动无源蜂鸣器输出特定频率方波，通过表驱动的乐谱数据结构播放多首曲子，并用点阵显示曲目编号、LED 指示当前音高。

**项目背景与定位：**

这是本科阶段完成的第一个完整嵌入式项目。目标不是做出多复杂的设备，而是**完整走通一次"硬件设计 → 固件开发 → 整机调试"的产品开发流程**，建立对嵌入式开发的感性认知与工程习惯。

在此之后，自学 STM32 平台并完成了中断、串口、DMA、定时器、ADC 等外设实验，构成了从 8051 到 Cortex-M 的技术迁移路径。

## 三、功能特性

- 定时器0 中断驱动蜂鸣器输出指定频率方波，音高由重装载值精确决定
- 三首内置曲目：Bad Apple（快节奏）、See You Again（含十六分音符）、两只老虎（慢节奏）
- 表驱动乐谱：新增曲目只需追加一个数组，**无需修改任何播放逻辑代码**
- 8×8 点阵动态扫描显示当前曲目编号（1/2/3）
- 7 只 LED 按音高分区指示当前音符
- 四个按键：播放/暂停、下一曲、上一曲；拨动开关切换单曲循环 / 列表循环
- 暂停时点阵持续显示曲目号，上电进入待机状态

## 六、核心实现

### 6.1 音高是怎么产生的

8051 定时器 0 工作在**模式 1（16 位）**，向上计数到 65536 溢出。装载值越小，计数值越多，溢出越慢。

```
半周期计数 = 65536 - 装载值
中断周期   = 半周期计数 × 机器周期
蜂鸣器频率 = 1 / (2 × 中断周期)     ← 两次中断翻转一次 = 一个完整方波
```

**机器周期**（8051 特有，12 分频）：

```
机器周期 = 12 / 11.0592MHz ≈ 1.085μs
```

**实例：L6 音（装载值 0xFB90 = 64400）**

```
半周期计数 = 65536 - 64400 = 1136
中断周期   = 1136 × 1.085μs ≈ 1232μs
方波周期   = 2 × 1232μs ≈ 2465μs
频率       = 1 / 2465μs ≈ 406Hz
```

所有音符频率常量在 `main.c` 中以宏定义给出（`L1` ~ `M7`），把"音名 → 装载值"这一步预先算好，运行期零计算开销。

### 6.2 时值是怎么计时的

定时器 1 同样工作在模式 1，**固定 20ms 中断一次**，作为毫秒级时基：

```
装载值 0xB800 = 47104
(65536 - 47104) × 1.085μs = 18432 × 1.085μs ≈ 20.0ms
```

每次中断把 `remain_time` 减去 20，音符播完时 `remain_time` 归零。

**为什么不用主循环里的软件延时计时？** 因为软件延时的实际时长受主循环执行时间、编译优化等级影响，不可控。定时器中断由硬件计时，精度与主循环负载无关。

### 6.3 表驱动：核心设计思路

**这是本项目最值得讲的设计。**

```c
typedef struct {
    unsigned int half_period;   /* 定时器0 周期计数值 → 音高 */
    unsigned int duration;      /* 持续毫秒数 → 时值 */
} gequ;

gequ code bad_apple[] = {
    {L6,F/2},{L7,F/2},{M1,F/2}, ...
    {0,0}   /* 曲终标志 */
};
```

**设计理由：**

若把旋律写成 `if-else` / `switch-case` 的播放流程，代码量会随曲目数膨胀且极难维护。改用数据驱动后：

- 新增曲目 = 追加一个数组，**播放逻辑一行不改**
- 曲终用 `{0, 0}` 判定 —— 因为 `0x0000` 已被定义为休止符 N，**一个字段同时兼任终止哨兵**，省掉额外的长度字段
- 时值用 `F`、`F/2`、`F/4` 表达（`F = 60000/BPM`），改 BPM 即可整体变速而不变音调

同一思路在协议解析、状态机设计中同样适用。

### 6.4 8051 内存模型与 `code` 关键字

8051 有三个独立的存储空间，**这是 8051 特有的、也是最容易踩坑的地方**：

| 关键字 | 存储位置 | 容量 | 用途 |
|---|---|---|---|
| `code` | 程序 Flash | 8KB | 常量表、乐谱数据 |
| `data` | 片内 RAM | 128B | 变量 |
| `xdata` | 片外 RAM | 依扩展 | 变量 |

本项目的乐谱数组动辄上百个字节，若不加 `code` 会被放进只有 128 字节的内部 RAM，**直接撑爆内存**。所以：

```c
gequ code bad_apple[] = { ... };        /* ✅ 常量表放 Flash */
gequ code * const song_list[] = {...};   /* ✅ 指针数组也放 Flash */
```

> **这是 8051 开发中最常见的坑之一**，面试时讲出来能证明真的踩过这类问题。

### 6.5 双定时器分工

| 定时器 | 模式 | 装载值 | 职责 |
|---|---|---|---|
| Timer0 | 模式 1（16 位） | 按音符变化 | **音高**：每次中断翻转蜂鸣器引脚 |
| Timer1 | 模式 1（16 位） | 固定 0xB800 | **时值**：每 20ms 递减 `remain_time` |

**关键约束：中断服务程序必须短小。** `t0_isr()` 里只做"翻转 + 重装载"两件事。若在其中加入显示刷新或按键扫描，中断周期会被拉长，音调立刻失真。

### 6.6 按键消抖与状态机

三个按键统一采用"**检测按下 → 延时消抖 → 二次确认 → 等待释放**"流程：

```c
if(KEY_PLAY == 0) {        /* 检测到按下（低电平有效） */
    delay(1000);            /* 延时消抖 */
    if(KEY_PLAY == 0) {     /* 二次确认，排除抖动误判 */
        is_playing = !is_playing;
        while(!KEY_PLAY);   /* 等待释放，防止连击 */
    }
}
```

切歌采用**请求标志 + 打断标志**机制：按键只置标志位并置 `need_break` 打断当前音符等待，主循环在安全点处理切歌请求。**这样中断里不会执行切歌逻辑，避免了在中断中改指针的危险。**

### 6.7 P0 口的上拉电阻

8051 的 P0 口是**开漏输出，不带内部上拉**，灌电流能力有限。驱动 8×8 点阵时，列选信号必须靠**外接上拉电阻阵列**（典型 10K×8）才能拉到高电平，否则点阵不亮。

这是 51 单片机最经典的硬件坑之一 —— 代码完全正确，硬件却没反应。

## 七、遇到的问题与解决

> 这一节是本项目最有价值的部分。**面试中被问得最多的不是"你做了什么"，而是"你遇到了什么问题、怎么解决的"。**

| 现象 | 根本原因 | 解决方法 |
|---|---|---|
| 播放到曲目末尾后越界访问 | `sizeof(song1)` 返回的是**字节数**而非元素个数，边界判断失效 | 改为 `sizeof(song1) / sizeof(song1[0])` |
| Keil 打开工程报文件找不到 | 工程文件里写的是失效的相对路径 `.\MusicBox_Keil_Project\main.c` | 改为 `..\User\main.c` |
| RAM 不够，程序跑飞 | 乐谱数组未加 `code`，被放进 128B 内部 RAM | 所有常量表加 `code` 关键字 |
| 音调不准 | 忽略了 8051 的 12 分频机器周期，按 1/晶振 直接算 | 公式中加入机器周期系数 12 |
| 中断后音调忽高忽低 | 中断服务程序里做了太多事，周期不稳定 | ISR 只保留翻转与重装载 |
| 点阵完全不亮 | P0 为开漏输出，缺少外部上拉电阻 | 加 10K×8 上拉电阻阵列 |

详细过程见 [`Docs/调试记录.md`](Docs/调试记录.md)。

## 八、硬件设计

### 8.1 原理图设计

- 工具：**Proteus**
- 关键考虑：
  - **P0 口必须外接 10K 上拉电阻阵列**，否则点阵不亮（见 6.7）
  - 蜂鸣器由 P1.0 经驱动三极管推动，**基极串 1K 限流电阻**，防止 MCU 引脚过流
  - 每个电源引脚旁各配一个 100nF 去耦电容
  - 复位电路采用上拉 + 10uF 电容 + 外部按键

### 8.2 PCB 设计

- 工具：嘉立创（打板）
- 布局考虑：点阵与蜂鸣器分居 PCB 两侧，减小振动与噪声干扰
- 走线考虑：电源线加宽，模拟与数字部分分区
- 器件：贴片焊接

### 8.3 焊接与调试

贴片焊接，逐模块上电验证：先测电源与复位，再测点阵显示，最后接入音频通路联调出声。

写在最后，因为这是我认为最有价值的部分：
