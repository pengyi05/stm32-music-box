## 一、硬件搭建阶段

### 问题 1：点阵完全不亮，代码反复检查无果

- **现象**：程序烧录后点阵没有任何显示，但用 LED 替换点阵后 LED 正常亮
- **环境**：AT89C52 + 8×8 点阵，Keil 编译，串口下载
- **排查过程**：
  1. 最先怀疑代码 —— 检查 `Display_Num()` 的行选/列选逻辑，扫描顺序正确
  2. 验证 P2 行选 —— 用示波器/万用表测各行输出电压，行选有波形
  3. 验证 P0 列选 —— **发现 P0 各脚始终为低电平，无波形**
  4. 查 8051 手册 —— P0 是**开漏输出**，内部无上拉电阻
- **根本原因**：P0 作为通用 IO 输出高电平时，必须外接上拉电阻（本设计用 10K×8 阵列），否则无法拉高
- **解决方法**：在 P0 各列线上并联 10K 上拉电阻阵列
- **收获**：**51 单片机的 P0 口是开漏输出，这是和 STM32 最大的差别之一**。硬件不工作时，先怀疑引脚电气特性，再怀疑代码

### 问题 2：蜂鸣器发声微弱且有杂音

- **现象**：蜂鸣器声音很小，混有明显杂音
- **排查过程**：
  1. 测 P1.0 输出波形，方波正常
  2. 怀疑是占空比不对 → 改用 50% 占空比，杂音减轻但音量仍小
  3. 测蜂鸣器两端电压，发现只有约 0.8V
- **根本原因**：蜂鸣器电流超出 MCU 引脚直接驱动能力（8051 单脚灌电流上限约 10mA），MCU 输出高电平时压降严重
- **解决方法**：加 NPN 三极管 + 基极限流电阻，由 MCU 只提供基极电流，集电极回路供电给蜂鸣器
- **收获**：**MCU 引脚不是电源**。凡是超过几十 mA 的负载，必须加驱动电路 —— 这一条在后面做电机驱动时是同样的原理

## 二、软件调试阶段

### 问题 3：播放到曲目末尾后越界访问，程序跑飞

- **现象**：前两首曲子播放正常，切到第三首时程序行为异常（音符乱跳或直接死机）
- **排查过程**：
  1. 发现只要把第三首数组长度改短，异常就消失 → 确认是越界
  2. 定位到数组末尾的判断条件：
     ```c
     if (idx >= sizeof(song1)) { idx = 0; }   /* ❌ 侥幸没出错 */
     ```
  3. 分析 `sizeof` 语义 —— `sizeof(数组名)` 返回的是**整个数组占用的字节数**，不是元素个数
- **根本原因**：`sizeof(song1)` = 元素数 × 2 字节，所以边界判断比实际宽松了将近一倍，**属于"侥幸正确"**。当换用元素类型不同的数组时立刻失效
- **解决方法**：
  ```c
  if (idx >= sizeof(song1) / sizeof(song1[0])) { idx = 0; }   /* ✅ */
  ```
  元素个数 = 总字节数 ÷ 单个元素字节数
- **收获**：**`sizeof` 有三种完全不同的行为，数组名传参时会退化成指针**。这类"看起来对"的代码最危险，因为一换场景就崩

### 问题 4：Keil 打开工程报错找不到源文件

- **现象**：工程能打开，但编译时提示找不到 `main.c`
- **排查过程**：
  1. 确认文件确实在 `Firmware/User/` 目录下
  2. 打开 `atm89.uvproj`，发现文件路径写的是 `.\MusicBox_Keil_Project\main.c` —— 这是**项目改名前的旧目录名**
- **根本原因**：工程文件里存的是**相对路径**，重命名/移动项目目录后路径失效
- **解决方法**：把工程文件中的路径改为 `..\User\main.c`，与实际目录结构对齐
- **收获**：Keil 工程文件的路径是相对的，**项目文件夹整体改名后一定要检查工程文件里的路径**

### 问题 5：RAM 不够，程序跑飞

- **现象**：加入第三首曲子后程序跑飞，加载后随机重启
- **排查过程**：
  1. 看编译输出的 RAM 使用量，已经接近 128B 上限
  2. 检查变量声明，发现乐谱数组没有加 `code`
- **根本原因**：8051 内部 RAM 只有 128 字节。乐谱数组不加 `code` 会被放进 RAM，几百字节的常量表直接把内存撑爆
- **解决方法**：所有常量表加 `code` 关键字
  ```c
  gequ code bad_apple[] = { ... };
  ```
- **收获**：**8051 有 code/data/xdata 三个独立存储空间，"数据放在哪"是 51 开发的第一课**。这跟"内存不够就加个数组"的直觉是反的

### 问题 6：音调明显不准

- **现象**：蜂鸣器发声但音调与预期差得远，且同一个音在不同曲目里音高不一致
- **排查过程**：
  1. 用示波器测 P1.0 输出频率，与目标频率对比
  2. 检查频率计算公式，发现漏掉了 8051 的 **12 分频**
- **根本原因**：8051 的机器周期 = 12 个振荡周期。最初按 `1/晶振` 算周期，**漏了 12 倍系数**
- **解决方法**：
  ```
  机器周期 = 12 / 11.0592MHz ≈ 1.085μs
  半周期计数 = 65536 - 装载值
  中断周期 = 半周期计数 × 1.085μs
  蜂鸣器频率 = 1 / (2 × 中断周期)
  ```
  全部音符装载值重算
- **收获**：**不同架构的定时器时基公式不一样，不能套用**。51 是 12 分频，STM32 直接按内核时钟算

### 问题 7：中断后音调忽高忽低

- **现象**：播放过程中偶尔出现一个明显走音的音符，随后恢复正常
- **排查过程**：
  1. 怀疑定时器重装载不准确 —— 检查发现 T0 采用**模式 1（16 位）**，重装载需要分两次写 TH0 和 TL0
  2. 意识到问题不在重装载值本身，而在**中断服务程序执行时间**：
     ```c
     void t0_isr(void) interrupt 1 {
         SPEAKER = ~SPEAKER;
         TH0 = current_period >> 8;     /* 重新装载 */
         TL0 = current_period & 0xFF;
     }
     ```
     如果 ISR 里还做了别的事（当时把显示刷新也放进来了），中断周期就被拉长，音调随之偏移
- **根本原因**：ISR 里混入了显示刷新等耗时操作，导致中断间隔不稳定
- **解决方法**：ISR 只保留"翻转 + 重装载"两件事，显示刷新全部放回主循环
- **收获**：**中断服务程序的第一原则是短**。这是嵌入式里最普适的性能直觉之一

## 三、硬件设计阶段复盘

### 设计上如果重做会改进的点

1. **P0 上拉电阻阵列改用排阻**（如 8×10K 排阻），比 8 只独立电阻更整齐、更省焊接时间
2. **蜂鸣器驱动三极管加基极下拉电阻**（10K 到地），避免 MCU 复位瞬间基极悬空导致蜂鸣器误响
3. **点阵与蜂鸣器之间的地走线加宽**，并把蜂鸣器远离 MCU 的晶振区域，减少电源噪声对定时器精度的影响
4. **增加一个串口测试点**，调试时能用串口助手打印状态，不必依赖点阵显示
5. **预留一组可外接的排针**，方便后续接示波器测波形

## 四、踩过的坑清单（速查）

| 坑 | 原因 | 解决 |
|---|---|---|
| 点阵不亮 | P0 开漏无上拉 | 外接 10K×8 上拉电阻阵列 |
| 蜂鸣器声音小有杂音 | 引脚直接驱动电流不足 | 加三极管 + 1K 基极电阻 |
| 曲末越界 | `sizeof(数组)` 是字节数 | 除以 `sizeof(数组[0])` |
| 程序随机跑飞 | 常量表未加 `code` 撑爆 128B RAM | 常量表加 `code` |
| 音调不准 | 漏算 8051 的 12 分频 | 时基公式乘 12 |
| 音调偶尔飘 | ISR 里混入显示刷新 | ISR 只做翻转与重装载 |
| Keil 找不到文件 | 工程文件相对路径失效 | 改为 `..\User\main.c` |
| 切歌时按键无响应 | 在等待音符的长循环里没检查标志位 | 加 `need_break` 打断标志 |
